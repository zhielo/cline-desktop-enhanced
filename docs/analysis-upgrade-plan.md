# Integrated first-party analysis upgrade: completion contract

All work stays in PR #111. No REA process/code is integrated. A build passing is not completion of this contract or evidence of superiority.

## Implemented on this branch

- Session Off/Static/Runtime workflow selection with preserved permissions; owned worker supervision and private, immutable, session/workspace-bound static receipts.
- JS/TS/JSX/TSX/package/ASAR inventory and syntax/module/Electron candidate relationships.
- Profile `cline-js-static/2`: bounded lexical local calls; immutable scalar, template and concatenation reduction; selected pure-return parameter substitution including const arrow/function expressions. Imported, mutable, recursive and side-effecting values remain unknown. No target executes.
- Basic Source Map v3 declared generated/original positions, separate untrusted source/sourceRoot labels and optional exact embedded source hashes. Indexed maps and runtime reconciliation are not supported. No source label is opened or fetched.
- Relative-path byte and finding changes, with retained hashed evidence for added/removed findings; paginated Comparison view while Off. Missing comparisons remain explicitly not-recorded. Prior profile-one receipt contents/hashes are not rewritten.
- Artifacts/Findings/Graph/Comparison/Timeline/Verification navigation, scoped capability readiness, owned fixture selfchecks and installed Windows acceptance assertions.

## Not yet complete — do not mark these applied

- Unified ingestion of the existing native/Android/runtime results into the same evidence schema, including supporting/contradictory evidence and useful next-test records.
- Deeper module export/entrypoint, preload exposure and native-boundary relationships; object/property and cross-module data-flow support. Never claim universal deobfuscation or complete program semantics.
- Combined native function dossiers: engine-qualified exact identity/image base, pseudocode, disassembly, references, relevant strings/callers/callees, versioned snapshots and explicit disagreement views. Existing exact selection and save/reopen-verified native project edits are preserved, not new dossier implementations.
- Static .NET metadata/IL inspection with owned fixtures and clearly limited coverage.
- JavaScript Inspector passive observation and separately approved active scenarios; exact selected target identity, static/runtime hash reconciliation and loaded/observed/not-observed/unknown distinctions. Runtime mode alone must never authorize them. Reuse the task approval/isolation lifecycle; do not expose a generic eval endpoint.
- Crash-reservation recovery with process-instance/ownership proof and atomic updates. Never clear by PID-only checks, steal leases, terminate an unrelated process, replay work or rewrite terminal evidence.
- Expanded fresh-install/upgrade/rollback, permission denial, malformed-input, limits, cancellation and recovery acceptance for those new capabilities.
- Actual same-authorized-fixture REA evaluation: correctness, unsupported claims, investigation effort, resource use and repeatability with comparable settings. A test harness or an app-only measurement is not a completed REA benchmark.

## Verification rule

For every item above, record the implemented operation, supported scope, real/owned fixture result, negative cases, permissions, packaged Windows result and remaining limitations. External provider presence is not health; imported reports are not authenticated observations. Keep the PR draft/unmerged until the owner-required scope and current-head gates are satisfied.
