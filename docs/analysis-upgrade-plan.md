# Integrated first-party analysis upgrade: completion contract

All work stays in PR #111. No REA process/code is integrated. Passing CI is not completion of this contract or evidence of superiority.

## Implemented scope

- Session Off/Static/Runtime workflow selection with preserved permissions; owned worker supervision and private, immutable, session/workspace-bound static receipts.
- JS/TS/JSX/TSX/package/ASAR inventory and syntax/module/Electron candidate relationships.
- Profile `cline-js-static/3`: closed inventory-only relative ES module bindings, named exports/reexports, lexical local/imported pure single-return function candidates, immutable scalar expressions and selected const scalar-object property reads. Writes, object escapes, getters, external/ambiguous modules, cycles, mutable and unsupported expressions remain unknown. No target executes. Earlier profile-one/two receipts are never rewritten.
- Basic Source Map v3 declarations, embedded source hashes and relative-path byte/finding comparison. No source label is opened/fetched. Indexed maps, universal deobfuscation and full semantics remain unsupported.
- Static managed PE32/PE32+ inspection: bounded CLI header/metadata streams, ECMA-335 table widths, TypeDef/MethodDef declarations and tiny/fat method IL bytes with exact offsets. No CLR load, high-level IL decompilation, method execution or arbitrary stream support. Non-managed PE files and malformed/oversized images fail closed/partial rather than imply support.
- Cross-domain snapshots of host-completed approved native/debugger/Android/runtime tasks when an exact local session/workspace is supplied and Analysis is enabled. Immutable task/request/result hashes, supporting exact-byte identity and explicit provider/runtime-source byte mismatches; next-test suggestions never initiate actions. Imported/provider output is a claim, not authenticated observation or behavioral certification. Snapshot retention is bounded and metadata failure must not replay execution.
- Native selected-function dossier snapshots: exact artifact hash, engine/version/address identity, retained disassembly, and explicit unknown pseudocode/reference/string/caller/callee/image-base fields when the provider does not supply them. Differing retained outputs are visible, not adjudicated correctness or automatic relocation. Existing verified project edits remain unchanged.
- Passive Node Inspector observation: separately reviewed one-time Debug task approval, exact selected PID/birth token and loopback-listener ownership checks before/after observation, bounded Debugger script/source retrieval and exact loaded-source hash comparison. ScriptParsed means loaded/parsed, not executed; absence in a bounded window is not absence. No eval/resume/breakpoint/launch endpoint is exposed. This attachment is not an OS sandbox and can affect the target.
- Crash-reservation recovery: trusted explicit idle-session action; persist machine namespace and original owner/worker birth proof before providing worker input; require both original instances gone; unavailable/foreign/legacy/malformed proof blocks. PID reuse never authorizes killing a replacement. Atomic compare-and-release appends a journal bound to the unchanged receipt digest, blocks late writes and does not rewrite terminal evidence, kill processes or replay work. Strong automatic namespace/probe support is Linux/Windows only; a Linux boot-ID fallback conservatively blocks recovery across reboot.
- Artifacts/Findings/Graph/Comparison/Timeline/Verification/Cross-domain/Dossiers/Disagreements views, explicit recovery and reviewed Inspector controls, scoped Setup Center readiness, required owned-fixture tests and existing installed Windows acceptance gates.

## Remaining scope — do not mark these complete

- Active JavaScript execution scenarios in a provisioned isolated runtime with independent Execute approval, cancellation/termination proof, dedicated owned fixtures and packaged acceptance. The app intentionally has no generic eval/resume shortcut.
- Rich native dossier components and validated image-base/relocation normalization across all supported engine adapters. Unknown components are not implementations of pseudocode or call graph recovery.
- Complete preload exposure/native-boundary and broader object/inter-module dataflow; semantic support above is deliberately bounded, not universal recovery.
- Additional .NET signature/token resolution, decoded IL/control-flow views and broader metadata coverage beyond retained declarations/IL bytes.
- Exact scenario-level cross-domain support/contradiction reconciliation beyond byte identity and provider output claims.
- New-capability installed Windows fresh-install/upgrade/rollback and fault-injection acceptance beyond the current core/desktop owned fixtures and existing installer journeys. Current-head CI must verify packaging; old passing artifacts do not validate new source.
- Actual same-authorized-fixture REA evaluation measuring correctness, unsupported claims, investigation effort, resource use and repeatability with comparable settings. A harness or an app-only measurement is not a completed REA benchmark.

## Verification rule

For every implemented operation record its supported scope, owned/real fixture result, negative cases, permissions, current-head packaged Windows result and remaining limitations. External provider presence is not health; imported reports are not authenticated observations. Keep the PR draft/unmerged until the owner-required scope and current-head gates are satisfied.
