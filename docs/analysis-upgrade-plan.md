# Integrated first-party analysis upgrade: completion contract

The static-analysis/evidence upgrade stays in PR #111. Active JS isolation should be a separate security-reviewed PR; additional independent PRs are allowed, but each must pass its own gates. No REA process/code is integrated. Passing CI is not completion of this contract or evidence of superiority.

## Implemented scope

- Session Off/Static/Runtime workflow selection with preserved permissions; owned worker supervision and private, immutable, session/workspace-bound static receipts.
- JS/TS/JSX/TSX/package/ASAR inventory and syntax/module/Electron candidate relationships.
- Profile `cline-js-static/6`: closed inventory-only relative ES module bindings, named exports/reexports, lexical local/imported pure single-return function candidates, immutable scalar expressions and selected const scalar-object property reads. Writes, object escapes, getters, external/ambiguous modules, cycles, mutable and unsupported expressions remain unknown. No target executes. Earlier profile-one/two/three/four/five receipts are never rewritten.
- Lexical Electron preload/native boundary candidates: named/namespace ES imports and selected const CommonJS bindings, literal exposed member paths, renderer-to-exposed-member associations, exact literal IPC-channel candidates, and direct exposed-wrapper/native-call associations. Explicit writes/deletes/updates/escapes, duplicate/getter/spread/prototype-sensitive shapes, shadowed bindings, ambiguous exposures, overwritten window APIs, incomplete mutation scans and unsupported aliases remain unknown/excluded. No Electron/native module loads, native export/ABI verification or runtime context/entrypoint co-execution is established.
- Basic Source Map v3 declarations, embedded source hashes and relative-path byte/finding comparison. No source label is opened/fetched. Indexed maps, universal deobfuscation and full semantics remain unsupported.
- Static managed PE32/PE32+ inspection: bounded CLI header/metadata streams, ECMA-335 table widths, TypeDef/MethodDef declarations, tiny/fat method IL bytes and bounded decoded instructions with exact offsets, normal-flow candidate graph edges, bounded local metadata-name/user-string token resolution, validated MethodList ownership for declaring types, and bounded method/field signature displays with exact blob provenance and exact decimal int64 preservation. Reserved/truncated opcodes or invalid/prefix-interior branch targets never produce guessed edges. Signature display supports bounded default method/field signatures, primitives, byrefs/pointers/SZ arrays and generic-variable/reference tokens; unsupported forms remain partial. Referenced type existence, external bindings, generic constraints and stack validity are not established. Display-name truncation is explicit. A real owned Roslyn assembly validates calls, declaring types/signatures, switch, strings and int64 without CLR execution. Small/fat bounded EH section declarations retain mapped byte offsets, catch/filter/finally/fault regions and entry association candidates. Unknown/malformed/chained-invalid sections yield no guessed regions; no dispatch precedence, exception transition, filter outcome, nesting or stack validity is established. Real owned Roslyn catch/finally fixtures are inspected without executing their DLL. No CLR load, high-level IL decompilation, method execution or arbitrary stream support. Non-managed PE files and malformed/oversized images fail closed/partial rather than imply support.
- Cross-domain snapshots of host-completed approved native/debugger/Android/runtime tasks when an exact local session/workspace is supplied and Analysis is enabled. Immutable task/request/result hashes, supporting exact-byte identity and explicit provider/runtime-source byte mismatches; next-test suggestions never initiate actions. Imported/provider output is a claim, not authenticated observation or behavioral certification. Snapshot retention is bounded and metadata failure must not replay execution.
- Native selected-function dossier snapshots: exact artifact hash, engine/version/address identity, retained disassembly, and explicit unknown pseudocode/reference/string/caller/callee/image-base fields when the provider does not supply them. LIEF preferred ELF link-time base and derived RVA are labeled separately from an unknown runtime base; Capstone/version identity, direct-call candidates and unique-file-mapped x86_64 RIP-relative ASCII reference candidates are retained. Selected-dossier incoming direct calls are explicitly incomplete candidates. Differing outputs are compared only with matching retained byte range, architecture and address-space scope; missing/mismatched scope is not comparable, never adjudicated correctness or automatic relocation. Existing verified project edits remain unchanged.
- Passive Node Inspector observation: separately reviewed one-time Debug task approval, exact selected PID/birth token and loopback-listener ownership checks before/after observation (Linux kernel socket inode matching; Windows absolute System32 numeric netstat with an exact single IPv4 loopback LISTENING row/PID, no slow CIM listener enumeration or unverified fallback), bounded Debugger script/source retrieval and exact loaded-source hash comparison. ScriptParsed means loaded/parsed, not executed; absence in a bounded window is not absence. No eval/resume/breakpoint/launch endpoint is exposed. This attachment is not an OS sandbox and can affect the target. Inspector profile `cline-js-inspector/2` adds explicit off-by-default console capture with separate sensitive-console/private-evidence requirements in the same exact one-time Debug request. Only bounded primitive previews/digests and opaque object markers from the approved source's uniquely matched script ID/exact source SHA are retained, with source coordinates and host receipt timestamps. At most 24 reports/8 arguments/160 preview characters are retained; raw string hashing is bounded to 16,384 characters, larger strings remain opaque. Buffered events before Runtime.enable acknowledgment, stale/future target timestamps (less than 1 ms receipt-clock rounding allowance), malformed frames and unbound/ambiguous script IDs are excluded. Only Runtime.enable/disable supplement the existing Debugger enable/source/disable command set; no eval, object-handle/property retrieval or launch. These are source-bound **protocol reports**, not authenticated VM execution, static call-site matching or scenario certification: the owned target can emulate Inspector messages. Target clock skew/history may discard legitimate reports, and missing reports never prove absence. Capture can persist secrets in private task evidence and requires explicit opt-in; opt-in resets between sessions and stale preparation responses cannot restore an invalidated plan.
- Crash-reservation recovery: trusted explicit idle-session action; persist machine namespace and original owner/worker birth proof before providing worker input; require both original instances gone; unavailable/foreign/legacy/malformed proof blocks. PID reuse never authorizes killing a replacement. Atomic compare-and-release appends a journal bound to the unchanged receipt digest, blocks late writes and does not rewrite terminal evidence, kill processes or replay work. Strong automatic namespace/probe support is Linux/Windows only; a Linux boot-ID fallback conservatively blocks recovery across reboot.
- Artifacts/Findings/Graph/Comparison/Timeline/Verification/Cross-domain/Dossiers/Disagreements views, explicit recovery and reviewed Inspector controls, scoped Setup Center readiness, required owned-fixture tests and existing installed Windows acceptance gates.

## Remaining scope — do not mark these complete

- Active JavaScript execution scenarios in a provisioned isolated runtime with independent Execute approval, cancellation/termination proof, dedicated owned fixtures and packaged acceptance. The app intentionally has no generic eval/resume shortcut.
- Rich native decompiler/pseudocode adapters, broader string/reference/indirect-call recovery and validated runtime image-base/relocation normalization across all supported engine adapters. Unknown components are not implementations of pseudocode or call graph recovery.
- Complete preload shape/alias/dynamic exposure and native export/ABI verification, plus broader object/inter-module dataflow; semantic support above is deliberately bounded, not universal recovery.
- Full .NET generic/function-pointer/array-shape/custom-modifier signature and external token resolution, exception dispatch/filter/nesting semantics, stack/type verification, high-level decompilation and broader metadata coverage beyond the bounded decoded IL/normal-flow candidates.
- Exact scenario-level cross-domain support/contradiction reconciliation beyond byte identity and provider output claims.
- New-capability installed Windows fresh-install/upgrade/rollback and fault-injection acceptance beyond the current core/desktop owned fixtures and existing installer journeys. Current-head CI must verify packaging; old passing artifacts do not validate new source.
- Actual same-authorized-fixture REA evaluation measuring correctness, unsupported claims, investigation effort, resource use and repeatability with comparable settings. A harness or an app-only measurement is not a completed REA benchmark.

## Verification rule

For every implemented operation record its supported scope, owned/real fixture result, negative cases, permissions, current-head packaged Windows result and remaining limitations. External provider presence is not health; imported reports are not authenticated observations. Keep the PR draft/unmerged until the owner-required scope and current-head gates are satisfied.


## Full-quality blocking checks and failure visibility

Consolidated validation builds the SDK and CLI prerequisites, then runs complete workspace `types` (including tests and smoke declarations) and workspace lint alongside the existing required suites. Build-only declarations are not a substitute for complete quality checks. Failed/timed-out/cancelled gates emit bounded fixed-name failure annotations; a CI step summary records every gate's status/timing and the exact checked commit. Raw logs, request content and environment values are not copied into annotations or the summary. Machine-readable evidence remains in the artifact. Windows failures must be diagnosed from the current checked merge/head evidence, not dismissed because a separate installer workflow passed. Native listener-probe errors remain fail-closed; no PID-only attachment, skip or timeout increase is permitted by this fix.
