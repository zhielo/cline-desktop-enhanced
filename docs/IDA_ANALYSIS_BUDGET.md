# IDA one-shot analysis budget

Built-in one-shot IDA analyze/decompile jobs default to a **60-minute auto-analysis phase budget** within a **75-minute overall process limit**. Startup, decompilation, database saving and output export share the remaining overall headroom. An unusually slow startup or an explicitly shorter overall deadline can still cap the analysis phase; no phase extends the total job deadline. Other engines retain their existing default and maximum limits. Managed worker lifetime limits are unchanged; this setting is for one-shot jobs, not a bypass of worker limits.

The host starts the phase clock when it observes the fixed script's `auto-analysis-waiting` event. Active elapsed/remaining time uses a monotonic clock, not CPU utilization, log activity or the system wall clock. An unchanged phase does not refill its budget. Auto-analysis completes immediately when IDA finishes; a one-hour budget is not a forced wait or an estimate of completion time.

Analysis environment → Refresh IDA jobs shows the analysis budget separately from the overall deadline. Enable live read-only refresh for fresh host samples every two seconds. Recorded receipts after host restart are explicitly historical snapshots, not live countdowns or fresh process-liveness proof. Completion percentages are unavailable rather than fabricated. Existing task cancellation remains available and only affects the supervised owned process tree.

At a phase timeout, the host writes a private per-job stop request. Fixed scripts check it at supported boundaries before/after `auto_wait` and can attempt to save only their isolated database. They exit nonzero after that save; no timed-out attempt is promoted as a successful analysis database or decompiler result. A five-second bounded grace is followed by the existing owned-process supervisor termination. **`auto_wait` can remain blocked and cannot be assumed to honor the stop request; a saved database is not guaranteed.** The overall hard timeout and explicit user cancellation retain existing immediate supervisor termination. Unconfirmed termination retains the workspace lease and is never labeled successful.

Optional structured inputs: `ida_phase_timeout_ms` can shorten the phase (1 second–60 minutes), and `timeout_ms` can explicitly shorten the whole job. Only explicit `engine:"ida"` requests may set `timeout_ms` above one hour, up to 75 minutes. No indefinite timeout or automatic extension/retry is provided.

Tests cover fake-clock phase entry, startup headroom, wall-clock changes, historical and completed snapshots, shortened deadlines, invalid limits, bounded stop grace, early completion, cancellation and generated Python behavior using owned API doubles. These tests do not certify a real IDA installation, processor or licensed decompiler. Full Windows installer and installed-app acceptance remain required before merge.
