# Task workspace UI upgrade

Scope: desktop task transcript, tool activity, task summary and reports. Base: `91062de2530b2787a416ab2da4ea929588904b9a`. This is a production-component upgrade, not a new agent runtime or a claim of Codex/Claude product parity.

## Delivered behavior

- **Execution and outcome remain separate.** Completed sessions use a neutral completion icon unless the existing evidence presenter confirms nonempty host checks for the exact declared plan/step/scope. Old unresolved failures are no longer discarded by a 200-entry projection cutoff. A finished tool is neutral, not a verification checkmark.
- **Compact live activity.** Routine completed tools and working narration collapse behind an explicit disclosure. Current/unresolved tools, host-bound failures/blockers, declared adverse outcomes, native execution failures, generated media and scheduled final answers remain discoverable. The most recent action stays visible when nothing needs attention. Interrupted runs remain fully visible. Activity restores the full chronological timeline; no fabricated semantic plan is inferred from tool counts.
- **Change review stays consolidated.** Routine edit diffs start closed and mount only on explicit disclosure. Counts and file labels remain visible. Changes and Review changes use the existing diff workspace, preserving staging/revert/restore safeguards and edit history. Per-action hunks are not represented as a net repository-wide diff.
- **Evidence and history are reachable.** Projection retains all available turn evidence and reports. UI mounts pages of 20 receipts and 10 turn summaries; closed historical reports do not mount their details. Paging uses receipt/turn IDs so newly arriving entries do not move an older page. Missing anchors fall back to latest data. Upstream history total is explicitly unknown, not claimed complete.
- **Activity-only reports remain useful without invented plans.** Recorded edit-tool completions are labeled not validated. Missing declared verification scope is explicit. Pending terminal results and adverse receipts stay in Remaining work; a missing terminal result prevents a fully verified overall outcome even when earlier declared checks passed.
- **Exports disclose coverage.** Summary exports include at most 200 evidence details and explicitly report included/available counts. A separate all-available-evidence JSON export preserves older loaded receipts without running tools. JSON redacts each string independently, preserving valid JSON even for large reports. Redaction remains best effort, and long individual strings may be truncated by the existing safety policy.
- **Command context is explicit.** Process-session rows show recorded action and process ID; executable/directory are displayed only when the returned snapshot belongs to the current session. Environment, argv and stdin are not copied into the context summary. Process follow-ups share their recorded process ID; they do not acquire invented liveness or automatic retries. Proceed while running explicitly continues the conversation without stopping or retrying the command.
- **Presentation state is session-owned.** Reports/Activity destination and tool/live/completed-work disclosures use an ephemeral bounded (512-entry) store keyed by session and stable message/run identity. No transcript content or credentials are persisted. Old presentation choices may be evicted when the cap is reached.
- **Readable and progressive.** Main status/receipt/report labels use larger text, visible disclosure chevrons, wrapping toolbars and keyboard-operable native controls. Expanded task plans are opt-in; repair warnings remain visible when collapsed. Existing questions, approvals, attachments, generated media, workspace-aware files, analysis, terminal and permission controls remain in place.

## Validation and boundaries

Local upgrade regression coverage includes >200 receipts, >50 turns, unresolved older failures, exact-scope verification, session filtering, stable page anchors while streaming, lazy history bodies, compact 1,000-action mounting, session disclosure restoration, interrupted tools, native errors, read-only destination routing, lazy diffs and process ownership/redaction. Required advanced validation already runs report tests; chat validation includes the new message tests.

A local isolated browser fixture renders the actual production React components with production-exported styles. It is not connected to a provider, shell or installed Windows application. Its matrix covers running/completed/cancelled/failed states, Chat/Activity/Reports, 390/768/1366px widths and dark/light themes (72 cases). This supplements, never replaces, required exact-candidate CI and installed Windows acceptance.

The 1,000-action regression checks that only the latest routine action mounts while collapsed and all 1,000 remain available on expansion. This is bounded rendering evidence, **not** an end-to-end latency/FPS/memory improvement claim. Projection still reads all loaded history; full Activity can mount many rows. Existing content-visibility behavior is not relabeled as true windowing. A future large-history virtualization design must preserve search, selection, accessibility and scroll anchoring.

No backend archive completeness, live process identity, file freshness, semantic correctness, signed distribution, automatic updates or universal bug-free behavior is claimed. Full Access, permission policy, unsigned manual artifact distribution and all release acceptance gates are unchanged. Merge only after the exact PR candidate passes required CI and installed-app acceptance.
